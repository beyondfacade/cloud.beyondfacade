## 2. ⚠️ 설계에 영향을 주는 치명적 발견 5가지

### 2-1. 서울시 추정매출: 2021년 이후만 잔존 → 코로나 전후 "매출" 비교 불가
2026-07-03 정책 변경으로 2021년 이전 추정매출 파일이 공식 경로에서 제거됨 (현재 2021~2025만 다운로드 가능).
- **영향**: brainstorming §5.4 코로나 회복 판정을 "2019년 매출 대비"로 설계했던 부분 수정 필요
- **대응**: 회복 판정 기준을 **매출 → 점포 수·개폐업률(LOCALDATA, 전 기간 보유)**로 변경. 매출 분석은 2021년 이후 구간(회복기 분석)에만 사용. 비공식 아카이브(캐글 등)의 2017~2020 파일은 라이선스 확인 후 보조로만
- ✅ **(2026-08-24 확보 완료)** GitHub 미러에서 2017~2021 상권-추정매출 연간 CSV 전량 확보 → `data/raw/seoul_sales/` (무결성 검증·SHA256 기록은 MANIFEST.md). 원천 KOGL 1유형이라 출처표시로 이용 가능. 주 지표는 개폐업률·점포수 유지, 매출은 교차검증·RAG 보조 근거로 활용
- 추가: 2024년부터 공간 기준이 상권영역 → 국가표준 단위구역으로 전환 중 — 시계열 연결 시 매핑 필요

### 2-2. 서울 생활인구: 행정동 기반 생산 2026-07-31 종료
국가표준격자(250m) 체계로 전환되어 행정동 데이터셋은 2026년 7월분이 마지막.
- **대응**: 파이프라인을 처음부터 **격자 기반 신규 데이터셋 + 격자→행정동 집계 매핑**으로 설계. 과거분(2017~2026.7)은 행정동 ZIP 파일로 적재

### 2-3. 상가정보 API는 개폐업 분석에 못 쓴다
현재 스냅샷 조회만 가능하고, 2022년 데이터 소스 개편으로 상가업소번호가 재생성되어 과거 분기 파일과 점포 단위 연계 불가.
- **대응**: 역할 분담 확정 — **상가정보 = 현재 경쟁밀도·좌표** (지오코딩 대체 효과, §2-4 참조), **LOCALDATA = 개폐업 시계열의 유일한 진실 소스** (인허가·폐업일자 전 기간 보유)

### 2-4. 브이월드 지오코더: 결과 저장 금지 조항
공식 문서에 "API 요청은 실시간 사용, 별도 DB 저장 불가" 명시 → 상가 주소 일괄 지오코딩 후 DB 캐싱하는 설계는 약관 위반 소지.
- **대응**: 좌표가 이미 포함된 원천(소진공 상가정보, 어린이집 표준데이터 등)을 우선 사용. 좌표 없는 소스(담배소매인 등)만 소량 지오코딩 — 필요 시 SGIS 지오코딩 API(권고 일 5만 회)로
- 브이월드 공통: 키 발급 시 서비스 도메인/IP 등록 필수, 서버사이드 호출은 `domain` 파라미터 필수. WFS 읍면동 경계는 1회 최대 1,000피처(서울 ~426개 동 = 1회 가능)

### 2-5. 상가 "임대료" 실거래 데이터는 존재하지 않음
전월세 신고제는 주택만 대상 — 상가 임대 실거래 API 자체가 없음.
- **대응**: 임대료·공실률은 **부동산원 R-ONE 임대동향조사(분기, 상권/지역 단위 평균)**로 대체. 개별 점포 임대료가 아닌 지역 평균임을 계산기(§brainstorming 8.1 ③)에 명시. 매매가는 국토부 상업업무용 API(2006~)로 정상 수급

## 3. 발급해야 할 계정·인증키 — 발급처(사이트)별 가이드

> 발급받은 키는 전부 `backend/.env`에 보관 (git 커밋 금지).
> **신청 순서 원칙: 승인 대기가 있는 곳(§3-1)부터 먼저 신청**하고, 즉시 발급(§3-2)은 그날 바로 받는다.

### 3-1. 승인·심사 대기 있음 — 가장 먼저 신청

**① 브이월드** — https://www.vworld.kr (P0 · 지도)
- [ ] 회원가입 → 오픈API → 인증키 발급 신청 (활용 서비스 URL 기입 필요 — 데모 도메인 기재)
- 용도: 배경지도 WMTS/XYZ 타일(midnight 다크 레이어), WFS 읍면동 경계, 검색 API
- ⚠️ 승인 대기 있음. 키 발급 시 서비스 도메인/IP 등록 필수, 서버사이드 호출은 `domain` 파라미터 필수
- ⚠️ 지오코더는 결과 저장 금지 약관(§2-4) — 좌표는 상가정보 API로 대체

**② LOCALDATA 지방행정인허가** — https://www.localdata.go.kr (P0 · 개폐업 시계열의 진실 소스)
- [ ] 별도 회원가입 → 마이페이지 → 인증키 신청
- 용도: 업종별(`opnSvcId`) 인허가·폐업 이력 API + 초기 적재용 월 단위 전체 파일
- ⚠️ 해외 IP 차단 정황 — 수집 서버는 국내 IP에서 호출
- ⚠️ 온프레미스 백엔드(Cloudflare Tunnel 경유)면 아웃바운드는 국내 IP라 문제 없음

**③ 온통청년** — https://www.youthcenter.go.kr (P2 · 청년정책 공고)
- [ ] 회원가입 → 청년정책 Open API 신청서 제출 → **담당자 심사 승인 대기**
- 리드타임이 가장 김 — 내일 최우선으로 신청만 걸어둘 것

**④ 빅카인즈** — https://www.bigkinds.or.kr (P2 · 뉴스, 선택)
- [ ] 무료 범위 확인 후 Open API 이용 신청서만 제출 (승인·비용 조건 확인 후 사용 여부 결정 — §7-3)
- MVP 뉴스 수집은 네이버 폴링으로 진행하므로 차단되어도 무방

### 3-2. 즉시~자동 발급 — 같은 날 완료 가능

**⑤ 공공데이터포털** — https://www.data.go.kr (계정 1개로 아래 전부 커버)
- [ ] 회원가입 → 각 API 페이지에서 "활용신청" (대부분 자동승인, 개발계정 일 10,000회/API)

  - [ ] 소진공 상가(상권)정보 API (현재 스냅샷·좌표 — P0)
  - [ ] 국토부 실거래가 상업업무용 매매 (15126463 — P0)
  - [ ] 부동산원 R-ONE 임대동향 (15134761 — P1)
  - [ ] K-Startup 사업공고 (B552735 — P1)
  - [ ] 보조금24 공공서비스 (P2)

- 용도: 뉴스 검색 API (일 25,000회) — 등록 즉시 폴링 수집 시작 (지연 = 시계열 손실)

- 용도: 외국인주민 현황 우회 조회

## 5. 소스별 상세 (검증 원본)

### 5.1 상권 코어

**LOCALDATA 인허가 (P0 — 개폐업 시계열의 진실 소스)**
- API: 자체 키, `opnSvcId`(업종코드, 190여 종) + `lastModTsBgn/End`(변경분) 호출, XML
- 초기 적재는 업종별 전체 파일(월 단위) → 이후 API 증분. 인허가·폐업일자 전 기간 포함
- 우리 10종 매핑: 노래연습장업, 휴게음식점, 미용업(세분), 체력단련장업, 당구장업, 인터넷컴퓨터게임시설제공업, 부동산중개업 + 학원(NEIS 별도) + 어린이집(별도 포털) + 편의점(상가정보+담배소매인 조합)

**소진공 상가(상권)정보** — data.go.kr 키, JSON/XML, 일 10,000회. 현재 스냅샷 전용. 분기별 전체 CSV(15083033)로 시점 스냅샷 자체 적재 병행

**서울시 상권분석서비스** — ZIP 파일만 (Open API 탭은 있으나 엔드포인트 미제공 확인). 추정매출-행정동(OA-22175)·상권(OA-15572)·점포(OA-15577) 등. 분기 갱신, 2021년 이후만

**서울 생활인구** — OA-14991(행정동·내국인). API는 최근 2개월, 과거분 ZIP(2017~). 시간대(0~23시)·성연령 포함. §2-2 격자 전환 주의

**국토부 실거래가 상업업무용 매매** — 15126463, XML, LAWD_CD(자치구 5자리)×DEAL_YMD(월) 반복 호출. 2006년 신고분부터. 최근 1~2개월 미완결(신고기한 30일), 지번 일부 비공개로 건물 단위 정밀 매칭 제한

### 5.2 정책자금 공고

**기업마당 (공고 수집 1순위)** — 엔드포인트 `bizinfo.go.kr/uss/rss/bizinfoApi.do`, 자체 키(`crtfcKey`), RSS(XML)+JSON. 필드: 공고명, 사업개요, 신청기간(마감일 확보), 소관/수행기관, 지원대상, hashtags(지역·업종). **업종은 구조화 필드가 없어 hashtags/지원대상 텍스트에서 LLM 추출** — brainstorming §8.1 구조화 추출 설계와 일치
- K-Startup — `apis.data.go.kr/B552735/kisedKstartupService01`, 접수기간·지원지역 구조화 필드 있음. 지역 필터 파라미터 미적용 사례 → 클라이언트 필터링
- 보조금24 — 7,500여 서비스, 지원대상 자유 텍스트 → 후처리 필요
- 중소벤처24 — LINK형(별도 신청·승인). 대안인 중기부 사업공고 API(15113297)는 일 100회·필드 빈약 → 후순위

### 5.3 지도

**브이월드** — WMTS/XYZ 타일(`api.vworld.kr/req/wmts/1.0.0/{key}/...`, midnight 다크 레이어 있음), WFS(`lt_c_ademd_info` 읍면동, GeoJSON 지원, 1회 1,000피처), 검색 API(DISTRICT 타입). quota 수치 비공표(제한 자체는 존재). 지오코더는 §2-4 저장 금지
**SGIS 대안** — 경계 `boundary/hadmarea.geojson`, 기본 좌표계 UTM-K(EPSG:5179) → 웹 지도용 변환 필요. 인구·가구 통계 결합 API 보유 — 지오코딩 포함 서버사이드에는 브이월드보다 유리한 면

## 6. 수집 인프라 제약 (확정)

1. **수집 서버는 국내 IP 필수** — localdata.go.kr 해외 IP 차단 정황(검증 중 ECONNREFUSED 확인). 클라우드 리전 선택 시 반영
2. 서울 열린데이터광장 API는 일 1,000회 제한 — 생활인구 등 대량분은 **파일 다운로드 파이프라인 병행** 설계
3. 스냅샷성 소스(상가정보·학원·어린이집)는 **주기 적재로 시계열을 자체 구축** — 지금 시작할수록 시계열 자산이 쌓임 (착수 지연 = 데이터 손실)
4. 브이월드 키 승인, 온통청년 심사, 기업마당 IP 등록은 **리드타임이 있으므로 1주차에 일괄 신청**
