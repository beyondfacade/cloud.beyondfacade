## 0. 방향 전환 — 네거티브 리포트 (2026-09-28 브레인스토밍)

> 문제 인식(팀장): 지금 프로젝트는 엔드유저 관점에서 방향이 애매하다. "어디에 창업하면 좋다"는 상권분석은
> 핀다·오픈업 등 이미 많다. **"이 동네에서 이 장사는 하지 마라 + 굳이 한다면 이 업종"** 을 말해주는
> 네거티브 방식은 드물다. 이 방향으로 간다.

### 0-1. 왜 우리 데이터가 네거티브에 유리한가

핀다·오픈업은 카드 매출 기반이라 "잘 되는 곳"에 강하다. 우리는 **지방행정 인허가 원천**이라 "망한 가게"를 개별 점포 단위로 셀 수 있다.

- 점포 349,196건에 **개업일·폐업일·좌표**가 전부 있다. 폐업 210,556건이 네거티브 리포트의 원료다.
- 2019년부터 시계열이라 **코호트 생존율**(2021년 개업 카페 중 3년 버틴 비율)을 동×업종별로 계산할 수 있다.
- 상권변화지표(영업·폐업 개월, 변화 4종)가 22분기 공백 없이 있고 서울 평균 베이스라인이 있어 "서울보다 빨리 문 닫는 동네"를 바로 판정한다.
- 담배소매인 95,402건 좌표는 편의점 진입 불가 판정에 그대로 쓴다. 담배권 없는 편의점은 성립하지 않는데 이걸 지도에 그려주는 서비스가 없다.

### 0-2. 핵심 구조: 레드 플래그 신호 → 판정 → 대안

판정을 점수 하나로 뭉개지 않는다. **독립된 경고 신호를 하나씩 켜는 방식.** 각 신호는 근거 문장과 원천 테이블을 갖고, 켜진 개수와 강도로 판정한다.
코드로는 CLAUDE.md §5 **Specification 패턴** — 신호 하나 = 클래스 하나(`is_satisfied_by(context)` + evidence), 합성은 Composite. 새 신호는 파일 추가로 끝난다.

### 0-3. 지도로 살리는 방법

- **가지 마라 지도**: 업종을 고르면 서울 427동이 회색~빨강 위험도 단계구분도. 기존 metric 파이프라인에 risk 지표 하나 추가 → 프론트 단계구분도·범례 그대로 재사용
- **폐업 마커**: 동 선택 시 최근 2년 폐업 점포를 좌표로 찍는다. "이 골목에서 카페 7개가 문 닫았다". 성능 가드(동 선택 시에만 로드)는 현행 규칙 그대로
- **편의점 담배권 원**: 담배소매인 좌표에 반경을 그려 빈 구역 표시
- **시간대 프로필 대조**: 사이드패널 하루 흐름 차트 위에 업종 매출 피크를 겹쳐 불일치 시각화 (두 데이터 모두 보유)

### 0-4. 리포트·관문 재편

관문 한 줄 "역삼동 카페" → 첫 화면이 **판정 카드**(큰 판정 + 켜진 신호 3~5개 + 대안 2줄).
리포트 섹션 순서: 판정 → 왜 안 되나(신호별 근거) → 그래도 한다면(시간대·임대료 상한·손익분기 매출) → 대안 동네·업종 → 대안 업종의 지원사업 공고.
- finance 계산기는 방향만 뒤집는다 — "이 동네 하위 25% 매출로는 손익분기를 못 넘는다"
- RAG: 뉴스에서 재개발·공사·임대료 분쟁 등 동네 악재를 붙이고, 공고는 대안 업종 쪽으로 연결

### 0-10. 최종 판정 산출 — 연도별 수치는 입력, 출력은 판정 하나 (2026-09-28)

- 시계열은 판정 카드의 "근거 보기"에서만 작은 추세선으로. 백엔드가 매일 배치로 동×업종당 **한 행**(점수·백분위·상위 신호 3개)을 미리 계산, 프론트는 그 행만 읽는다.

**필요한 ML — 3개, 딥러닝 불필요.** 인허가 폐업일자가 곧 정답 라벨이라 지도학습이 된다.

| # | 모델 | 역할 | 출력 | 라이브러리 |
|---|---|---|---|---|
| ① | 생존 분석 (Kaplan-Meier + Cox 비례위험) | "얼마나 버티나". 영업 중인 가게를 검열 처리해 최근 개업 왜곡 제거 | 동×업종 1·2·3년 생존율, **서울 대비 위험비(hazard ratio)** | lifelines |
| ② | 폐업 위험 분류기 (Gradient Boosting) | 판정 점수의 본체. 라벨 = 개업 후 3년 내 폐업, 피처 = **개업 시점 기준** 동×업종 지표(밀도·순유출·매출 추세·인구·임대료·프로필 유형·프랜차이즈 비중·충격 회복) | "지금 열면 3년 내 폐업 확률" + SHAP 기여도(= "왜 안 되나" 신호) | LightGBM + shap |
| ③ | 동네 유사도 (k-NN) | "굳이 카페라면 옆 동네". 6종 동네 유형 프로필 벡터의 최근접 이웃 | 유사 동 상위 N | scikit-learn |

- 대안 업종 추천은 별도 모델이 아니다 — ②를 같은 동에서 판정 대상 업종 전부에 돌려 확률 낮은 순.
- LLM은 판정에 관여시키지 않는다. **판정은 모델·규칙, 문장은 LLM.**
- 추세 판정에 Prophet 등 시계열 모델은 과함 — 최근 8분기 기울기면 된다.

**상대평가는 ML로 자연스럽게 풀린다 — 두 방향 정규화**
- 업종 안에서 동끼리: 카페 위험 확률을 427동 백분위로 → 상위 20% = 🔴. 임계값을 사람이 정하지 않고 분포가 정한다.
- 동 안에서 업종끼리: 같은 동에서 판정 대상 업종 확률 순위 → "그나마 나은 건 분식".
- 절대 기준 하나(폐업률 15% 등)는 업종별 기저율이 달라 카페와 부동산을 같은 잣대로 못 잰다. → **§0-8 첫 항목 답: 상대평가, 임계값은 모델 확률 분포에서.**

**백테스트** = ②의 시간 분할. 2019~2022 개업으로 학습, 2023 개업으로 검증 → "🔴 집단 실제 폐업률 vs 나머지"(§0-5의 한 장). 지표: AUC·캘리브레이션·🔴 집단 lift.

**조심할 것**
- 라벨 오염: 인허가 폐업에 양도·양수(사업자 변경)가 폐업+개업으로 잡힘 → 서울시 상권변화지표의 폐업 개월과 교차검증
- 누수: 피처는 개업 시점 이전 값만. 이후 값이 섞이면 백테스트가 거짓으로 좋아진다
- 학원·어린이집은 라벨이 없어 ② 불가 → §0-11 보조축으로 전환

**구현 위치**: 신규 `risk` BC — 새벽 로컬 배치(학습) + 결과 테이블 `region_industry_risk`(점수·백분위·상위 신호 JSON) + 조회 API. 도커 이미지에는 결과만(fp16 색인을 로컬 배치로 돌리는 현행 패턴과 동일).

### 0-11. 학원·어린이집 = 판정 대상이 아니라 보조축 (2026-09-28 결정)

> 팀장 결정: 학원·어린이집은 상권으로 보면 인구가 많을수록 둘 다 늘고 없으면 줄어드는 **정주 인구의 지표**다. 처음부터 실거주 인구가 얼마나 있는지 보려고 넣은 것이니 판정 업종에서 빼고 **보조축(feature)** 으로 쓴다.

- **판정 대상 업종**: 카페·미용실·PC방·노래방·부동산·편의점·헬스장·당구장 8종 + 음식 1차 6종(§0-9) = **14종**. 학원·어린이집은 업종 select·관문·판정 카드에서 뺀다.
- **편의점은 verdict BC 1단계 판정에서 추가로 제외(판정 13종, 9/29 Ruling A)** — 스냅샷 전용 원천이라 store 인허가 행이 없어 신호 3개가 영구 불가하다. §0-7 4번(업종 특화 신호, 담배권 원) 단계에서 재포함한다. 위 14종은 업종 select·metric BC 노출 기준으로는 그대로다.
- **보조축으로 쓰는 값** (동 단위 피처, 모델 ②와 규칙 신호 양쪽에 입력):
  - 어린이집 정원·현원·충원율(주간 스냅샷) → 영유아 가구 실거주 강도. 0~6세 주민등록 인구와 함께 "가족 정주형 동네" 축
  - 학원 수·강좌 수(academy_course) → 학령 가구 실거주 강도. 7~18세 인구와 함께
  - 두 값의 **추세**(스냅샷 누적·연도별 학원 수)는 인구 이탈 신호(§0-2)의 보조 근거
- 이 축이 말해주는 것: "낮에 비고 저녁에 차는 주거지"인지 "직장인만 있는 오피스 동네"인지. 미용실·분식·학원가 카페처럼 정주 수요 업종의 판정에 특히 유효하다.
- 기존 적재·크론(어린이집 주간, 학원)은 그대로 유지한다. `region_industry_metric`의 academy·childcare 행은 남겨두되 화면 노출만 끊는다(폐업률·성장률 NULL 처리 로직은 이미 있음).
- 후속: `SNAPSHOT_INDUSTRIES`·`NO_CLOSURE_HISTORY_INDUSTRIES`(프론트)와 `_NO_CLOSURE_HISTORY`(백엔드 metric)는 두 업종이 판정 대상에서 빠지면 **예외 처리 자체가 불필요**해진다 → 판정 UI 전환 시 정리.
