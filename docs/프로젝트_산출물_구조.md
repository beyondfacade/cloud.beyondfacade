# 프로젝트 개발 산출물 구조 — beyondfacade 서울 상권 분석 플랫폼

> 서울시 행정동 단위 상권 데이터를 수집·적재하고, 지도 기반으로 시각화하며,
> RAG + 단일 에이전트가 실시간 AI 분석 리포트를 스트리밍하는 창업 의사결정 지원 서비스.
>
> - 백엔드: FastAPI + SQLAlchemy + PostgreSQL(pgvector) — 모듈러 모놀리스, 포트 8200(dev 8201)
> - 프론트엔드: Next.js(App Router) + React + TypeScript + Tailwind v4 + TanStack Query + MapLibre GL — 포트 3200
> - AI: Ollama 로컬(qwen3-embedding:4b, gemma3:12b) + Google Gemini(평가·백업)

## 2. 개발 항목 요구사항정의서

- **개발개요**
  - 예비 창업자가 "이 동네에 이 업종으로 차려도 되는가"를 데이터와 AI 근거로 판단하도록 돕는 웹 서비스
- **주요 기능**
  - 서울 427개 행정동 지도 탐색 + 동 단위 상권 지표(개폐업률·생존율·점포수 등) 시각화
  - 업종·연도별 지표 조회, 인구 구조·임대료·금리·상권 충격 이벤트 등 보조 지표 패널
  - AI 분석 탭: 지역×업종 입력 → 에이전트가 데이터 조회·RAG 검색을 수행하며 5섹션 리포트(종합판정/시장/충격/지원금/계산기)를 SSE로 실시간 스트리밍
- **기술 요구사항**
  - 요구사항 #1 (지도 시각화): 행정동 폴리곤 위 지표 색상 스케일 렌더링, 라이트/다크 테마 대응, 동 선택 시에만 점 데이터 로드(성능 가드)
  - 요구사항 #2 (데이터 자동 수집): 공공·금융 API(서울시·SEMAS·ECOS·R-ONE·네이버뉴스 등)를 크론 기반 자동 수집·정규화 적재, 수집 이력 추적
  - 요구사항 #3 (AI 분석 리포트): 지원금 공고·뉴스의 벡터 검색(RAG) + 정형 데이터 도구 7종을 가진 단일 에이전트가 근거 인용(citations: fact/signal 등급) 포함 리포트를 생성, 응답 규칙 4종(차별 표현 금지·재난기 폐업률 왜곡 보정·금융 규제 경계·신뢰 등급 표기) 준수

## 3. 개발 항목 상위 설계서

- **개발개요**
  - 모듈러 모놀리스 + 헥사고날/클린 아키텍처 + DDD: 1 ERD 테이블 = 1 프랙탈 11-파일 세트 = 1 AI 위임 단위
- **Data Flow (아키텍쳐링)**
  ```
  [공공·금융 API] → (크론 수집 CLI) → [PostgreSQL: BC별 테이블]
                                          │
  [funding·news 원문] → (새벽 색인 배치) → [rag_chunk: vector(1536) + HNSW]
                                          │
  [Next.js 프론트 3200] ⇄ REST /api/v1 ⇄ [FastAPI 8200: BC 라우터]
        └ AI 분석 탭 ⇄ POST /analysis + SSE ⇄ [agent BC: 루프+도구 7종+RAG 검색]
                                                    └ LLMGatewayPort ⇄ gemma3(Ollama) / Gemini
  ```
- **개발환경**
  - Linux, Python venv(FastAPI·SQLAlchemy·pgvector·httpx·sentence-transformers), Node(Next.js·Vitest), 도커(PostgreSQL·백엔드 이미지), NVIDIA GPU 16GB(로컬 LLM·fp16 임베딩), Ollama
- **주요 기술요소**
  - 헥사고날 포트/어댑터(입출력 포트 ABC + DI Composition Root), pgvector HNSW 코사인 검색, 임베딩 혼용 구도(색인 fp16/쿼리 Q4, 1536차원 고정, embedded_by 모델 추적), SSE 스트리밍(`event: {type}\ndata: {json}`), GoF 레지스트리/Strategy(조건 분기 대체), TDD Red→Green
- **요구사항 별 기술요소**
  - 요구사항 #1 — 구현목표/설명: MapLibre GL WebGL 렌더링 + 디자인 토큰 브리징(`getComputedStyle` 색 계산), 단일 색상 스케일 원천(`makeMetricColorScale`)으로 지도·범례 동기화
  - 요구사항 #2 — 구현목표/설명: BC별 게이트웨이 어댑터(외부 API) + 수집 CLI + 크론, 실데이터 컬럼 기반 ERD(1NF→3NF), 증분 수집 커서
  - 요구사항 #3 — 구현목표/설명: rag BC(색인·검색·평가)와 agent BC(루프·도구·SSE) 분리, 기존 UseCase를 도구로 재사용(Port=Tool), 프론트 mock과 바이트 수준 동일한 SSE 계약
- **시나리오 테스트**
  - BC별 pytest(TDD, Fake 포트/실 DB 겸용), 프론트 mock 라우트 계약 테스트, Recall@5·MRR 검색 품질 하네스, 에이전트 시나리오 10종 × 모델 2종 비교 평가(계획)

## 6. 출품 시나리오

- **개발개요**
  - "데이터 + AI 근거로 창업 입지를 판단하는 상권 분석 플랫폼" — 수집 자동화부터 AI 리포트까지 엔드투엔드 시연
- **Data Flow (아키텍쳐링)**
  - §3 상위 설계 Data Flow와 동일 (수집 → 적재 → 시각화 → RAG/에이전트 → SSE 리포트)
- **목적과 기능**
  - 행정동×업종 선택만으로 지표 시각화 + 근거 인용이 달린 AI 분석 리포트를 1분 내 제공
- **대외 서비스 API 계획**
  - REST `/api/v1/*`(지표·마스터·지원금·뉴스 등 BC별 조회), `POST /analysis` + `GET /analysis/{id}/events`(SSE) — `docs/api.md` 명세 기준 외부 공개 검토
- **DEMO (상세 설계에 맞는 데모시연)**
  1. 지도에서 역삼1동 선택 → 카페 업종 지표(개폐업·생존율) 및 인구·임대료 패널 확인
  2. AI 분석 탭 실행 → 에이전트 진행 패널(orchestrator→market→shock→funding 상태 전환)과 도구 호출 로그 실시간 표시
  3. 5섹션 리포트 스트리밍 수신(종합판정/시장/충격/지원금/월세vs매입 계산기) + 인용 근거(fact/signal 등급) 확인
  4. (비교 데모) 데이터가 없는 업종 입력 시 "데이터 부족" 우아 처리 확인
