## 2. 프로젝트 개요

코로나 이후 상권은 거리두기·영업제한 같은 **외생 충격**과 유동인구·임대료·경쟁밀도 같은
**전통적 상권 요인**이 겹치며 폐업과 회복을 반복해 왔다.
본 프로젝트는 **공공데이터**를 구조화(Chunking)하여 Hybrid RAG 파이프라인에 올리고,
**초기 창업 희망자**에게 "이 지역에서 이 업종으로 창업해도 되는가"에 대한
근거 있는 분석을 제공하는 에이전트를 개발한다.

**타겟 업종 (10종)**: 카페 · 노래방 · 부동산(공인중개사무소) · 편의점 · 미용실 · PC방 · 헬스장 · 당구장 · 학원 · 어린이집
(핵심 3종 = 카페·노래방·부동산 — 상세 분석은 §3, 확장 7종은 §3.5, 학원 서브카테고리는 §3.6)

## 3. 타겟 업종 3종 브레인스토밍

세 업종은 우연이 아니라 **수요 동인이 서로 다른 세 유형**을 대표한다.
이 구도가 MVP의 강점이다 — 하나의 분석 모델이 세 유형 모두에서 작동하면 일반화 가능성이 검증된다.

### 3.1 카페 — 일상소비형 (경쟁밀도 민감)

- **강점**: 창업 희망자 수요가 가장 큰 대표 업종. 점포 수가 많아 데이터가 풍부하고 통계적 분석이 안정적.
- **핵심 질문**: 포화 상권인가? 반경 내 경쟁점 수 대비 배후 수요(상주+직장인구)가 충분한가?
- **지배 변수**: 유동인구, 경쟁점포 밀도, 임대료, 배후인구, 프랜차이즈 진입 여부.
- **주의점**: 저가 프랜차이즈(메가커피 등) 급증으로 개인 카페와 프랜차이즈를 구분해서 봐야 함.

### 3.2 노래방 — 여가형 (외생 충격 민감)

- **강점**: 코로나 집합금지의 직격탄을 맞은 대표 업종 → **특이변수(정책 충격)의 효과를 가장 선명하게 보여주는 실험군**. "정책 공시 RAG 파이프라인"이라는 팀명과도 정합.
- **핵심 질문**: 코로나 충격에서 회복된 상권인가, 구조적으로 쇠퇴한 상권인가? (일시적 폐업 vs 수요 자체의 소멸)
- **지배 변수**: 거리두기 정책 이력, 야간 유동인구, 주변 유흥·음식점 집적도, 코인노래방 vs 일반노래방 구분.
- **주의점**: 점포 수가 카페보다 훨씬 적어 동 단위 분석 시 표본이 얇을 수 있음 → 상권(구) 단위 집계 병행.

### 3.3 부동산(공인중개사무소) — 경기민감형 (거시변수 민감)

- **강점**: 유동인구보다 **금리·거래량·부동산 경기**에 좌우되는 업종 → 전통 상권분석만으로는 설명이 안 되는 반례 제공. 개폐업 데이터(국토부 중개업 등록)가 정확하고 완전함.
- **핵심 질문**: 관할 지역의 거래량 대비 중개업소 수가 과밀한가? 금리 사이클상 지금이 진입 시점인가?
- **지배 변수**: 아파트/주택 거래량, 기준금리, 관할 세대수, 경쟁 중개업소 수, 재개발·입주 예정 물량.
- **주의점**: 세 업종 중 변수 구조가 가장 이질적 → 분석 모델을 업종별 **Strategy 패턴**으로 분리할 근거가 됨(if 업종 분기 금지, CLAUDE.md §5).

### 3.4 종합 평가

| | 카페 | 노래방 | 부동산 |
|---|---|---|---|
| 수요 유형 | 일상소비 | 여가 | 경기민감 |
| 코로나 민감도 | 중 | **최상** | 하 (금리가 지배) |
| 데이터 풍부도 | 최상 | 중 | 상 |
| 전통 상권변수 설명력 | 높음 | 중간 | 낮음 |
| MVP 역할 | 기준 모델 | 특이변수 검증 | 반례·일반화 검증 |

**결론: 타겟 3종 구성은 적절하다.**

**지역 범위 (확정): 서울 한정**

- 근거: 추정매출·시간대별 유동인구(생활인구)·개폐업률이 완결된 공공데이터는 서울시 상권분석서비스가 유일 → 서울에서만 풀 지표 제공 가능
- 지표 산출 로직은 전국 공통 데이터(LOCALDATA·상가정보·실거래가) 기반 **코어 지표**와 서울 전용 데이터 기반 **확장 지표**를 코드 레벨에서 분리해 둔다 → 추후 수도권·전국 확장 시 코어 지표는 데이터 추가 없이 동작
- 수도권(경기·인천) 확장은 post-MVP 후보 (경기도 공공데이터드림 등 대체 데이터 확인 후)

### 3.5 업종 확장 방향

**원칙: 업종을 하나씩 추가하는 게 아니라 "수요 동인 유형" 축으로 확장한다.**
현재 3종은 각각 일상소비형·여가형·경기민감형의 대표다. 확장이란 ① 각 유형에 업종을 더 채우거나 ② 새 유형을 추가하는 것이다.

**확정 업종 (10종):**

| 수요 동인 유형 | 업종 |
|---|---|
| 일상소비형 (경쟁밀도 민감) | 카페, **편의점, 미용실** |
| 여가형 (외생충격 민감) | 노래방, **PC방, 헬스장, 당구장** |
| 경기민감형 (거시변수 민감) | 부동산 |
| 인구구조 민감형 | **학원, 어린이집** |

추가 후보(추후): 일반음식점·베이커리, 스크린골프, 인테리어업, 노인복지 업종.

**확장 7종 상세 브레인스토밍:**

**편의점 (일상소비형)**
- 핵심 질문: 전국적 포화 상태에서 "출점 여백이 남은 미세 입지가 있는가"
- 지배 변수: 유동+상주 혼합 수요, 야간 수요, 1인가구 비율, 브랜드별 근접출점 현황
- **결정적 변수 — 담배소매인 지정**: 편의점 수익의 핵심인 담배 판매권은 지자체가 거리 제한(서울 기준 인접 소매인과 최소 거리)으로 지정 → **담배소매인 지정 현황(지자체 공개)이 사실상 출점 가능 여부를 결정**. 이 데이터를 넣으면 경쟁 서비스에 없는 분석이 됨
- 주의: 인허가상 "편의점" 단일 코드가 없음(담배·휴게음식 복합) → 상가정보 업종분류로 식별. 가맹 양수도가 폐업으로 잡히는 노이즈
- 특이변수: 최저임금(야간 무인화·24시간 포기 추세), 1인가구 증가(순풍)

**미용실 (일상소비형)**
- 핵심 질문: "인구 천명당 미용실 수" 포화도 — 유동인구보다 **배후 상주인구·단골 기반** 업종
- 지배 변수: 상주인구(성별·연령), 경쟁밀도, 임대료 민감도 낮음(2층·이면도로 가능 → 1층 프리미엄 불필요)
- 기회: LOCALDATA 미용업이 일반(헤어)/피부/네일 등으로 세분되어 있음 → **학원과 동일한 서브카테고리 프레임(§3.6) 재사용**
- 특이변수: 1인 미용실·공유미용실 급증(초저자본 창업 트렌드)

**PC방 (여가형)**
- 핵심 질문: 코로나 회복이 아니라 **구조적 쇠퇴(모바일 게임·고성능 개인 PC) 속에서 생존 가능한 입지인가** — 노래방과 함께 "회복 vs 소멸" 판별의 대표 사례
- 지배 변수: 10~20대 인구, 학교·대학 인접성, 야간 유동, 좌석 수 대형화 경쟁
- 인허가: "인터넷컴퓨터게임시설제공업" (LOCALDATA 제공, 데이터 깨끗함)
- 계산기 연계: 장비 투자비가 커서 창업비용 시뮬레이션(§8.1 ②)의 업종별 표준비용 차별화가 필요한 대표 업종

**헬스장 (여가형)**
- 핵심 질문: 코로나 직격 후 **가장 강하게 회복한 여가 업종** — 배후 주거+직장 인구의 출퇴근 동선에 있는가
- 지배 변수: 20~40대 인구, 주거·오피스 혼합도, 평당 임대료(대면적 필요, 지하·상층 가능)
- 주의: 인허가는 "체력단련장업"이지만 **필라테스·요가·크로스핏은 신고 체계가 달라 데이터에서 누락** → 경쟁밀도가 실제보다 낮게 잡히는 함정. 이 한계를 응답에 명시해야 함
- 특이변수: 회원권 선불 구조 → "먹튀 폐업" 이슈 → 폐업 예측 정보의 사회적 가치가 특히 큰 업종

**당구장 (여가형)**
- 핵심 질문: 사양 업종이었다가 **중장년 여가로 재부흥** — 노래방·PC방과 회복 패턴이 다른 제3의 궤적
- 지배 변수: 중장년(40~60대) 인구, 야간 상권, 넓은 면적·상층 입지(임대료 축이 다름)
- 인허가: "당구장업" (체육시설업, 데이터 양호). 점포 수가 적어 행정동 단위 표본이 얇음 → 자치구 단위 병행 (노래방과 동일 이슈)
- **여가형 3종 세트의 가치**: PC방(10~20대) · 노래방(전 세대) · 당구장(중장년) → 한 상권의 **세대별 여가 수요 프로파일**을 그릴 수 있음

**어린이집 (인구구조 민감형)**
- 성격이 근본적으로 다름: 자유 창업이 아니라 **인가제**(구청 수요조사 통과 필요) + 저출산으로 구조적 축소 시장 → 에이전트 응답에 인가 절차 안내 필수
- 핵심 질문: "이 동네에 0~5세 인구가 향후 5년간 존재할 것인가" — **10종 중 유일하게 미래 인구 추계가 필요한 업종**
- **결정적 데이터 — 정원 대비 현원**: 어린이집정보공개포털이 정원·현원을 공개 → **수요 초과/미달을 직접 관측 가능**. 다른 업종은 매출을 추정하지만 어린이집은 가동률이 그대로 보임
- 지배 변수: 행정동 0~5세 인구 추이, 신축 아파트 입주 물량, 국공립 확충 정책(민간에는 경쟁 압력)

**업종 간 교차 시그널 (10종 확장의 진짜 가치):**

업종이 늘면 분석이 10배 되는 게 아니라, **업종 간 신호가 서로의 선행지표**가 된다:

| 시그널 | 해석 |
|---|---|
| 어린이집 폐원 증가 | 0~5세 인구 유출 → **수년 후 초등 대상 학원 수요 감소의 선행지표** |
| 편의점 신규 출점 | 편의점 본사가 이미 상권분석을 하고 들어옴 → **"검증된 상권" 프록시** |
| 여가형 3종 동반 침체 | 상권 자체의 야간 활력 붕괴 (개별 업종 문제가 아님) |
| 헬스장·당구장 상층 공실 채움 | 1층 임대료 부담을 피한 수요 → 임대료 상승기 신호 |

→ 이 교차 시그널이 단일 업종 분석 서비스와의 차별점. RAG 응답에서 "인접 업종 신호"를 근거로 인용하는 기능을 post-MVP 로드맵에 넣을 가치 있음.

**인허가 업종코드 매핑 (§4.3 체크리스트 연동):**
업종마다 LOCALDATA 인허가명이 전부 다름 — 노래연습장업, 휴게음식점(카페), 부동산중개업, 담배소매인(편의점), 미용업(세분 3종), 인터넷컴퓨터게임시설제공업(PC방), 체력단련장업(헬스장), 당구장업, 학원(교육청 NEIS 별도 체계), 어린이집(복지부 별도 포털). **착수 1주차에 10종 전체의 코드-데이터소스 매핑표부터 확정할 것.**

**"AI가 하니까 업종 추가는 공짜" — 절반만 맞다:**
- ✅ 맞는 부분: 파이프라인·11-File Set·지도 시각화는 업종코드 파라미터만 다른 동일 구조 → 구현 한계비용 ≈ 0. 서울시 상권분석서비스도 생활밀접업종 ~100종을 이미 제공하므로 데이터도 있다.
- ❌ 남는 병목: **업종별 변수 설계와 평가셋**. 어떤 변수가 그 업종을 지배하는지(예: 학원은 학령인구, 헬스장은 배후 주거인구) 정의하고, Recall@5 평가 질문-정답 쌍을 만드는 건 여전히 사람 검증이 필요하다. 확장 비용은 코드가 아니라 검증에 있다.

**실행 방식:**
1. 파이프라인은 처음부터 **업종-불가지론(agnostic)**하게 구현: 업종코드·지배변수 세트를 설정으로 분리, 분석 로직은 유형별 Strategy 클래스 (§5 GoF 규칙 — `if 업종` 분기 금지)
2. 구현·검증 순서는 유형당 1개 대표 업종 먼저 (카페→노래방→부동산→학원), 이후 같은 유형 내 업종은 설정 추가로 확장
3. 데모에는 검증(평가셋 통과) 완료된 업종만 노출

### 3.6 학원 서브카테고리 설계

학원은 단일 업종으로 묶으면 분석이 무의미하다 — 수학학원과 피아노학원은 경쟁 관계가 아니고,
수요 인구도 다르다. **하지만 별도 업종 10개로 쪼개는 게 아니라, "학원 1업종 × 2축 서브카테고리"로 모델링한다.**

**2축 분류:**

| 축 | 값 | 데이터 근거 |
|---|---|---|
| 교습계열 | 입시·보습 / 예체능 / 외국어 / 직업·기술 / 독서실·스터디 | 서울시 학원·교습소 데이터의 **교습계열·교습과정 필드** (원본 제공) |
| 대상 학년 | 초등 / 중등 / 고등 / 성인 | 교습과정명에서 **LLM 구조화 추출** (예: "고등수학" → 고등) — §8.1 공고 추출과 동일 기법 |

**데이터가 이미 지원한다:**
- 서울시 열린데이터광장 "학원·교습소 정보" (교육청 NEIS 원천): 교습계열, 교습과정, 정원, **수강료**까지 제공 → 타 업종에 없는 가격 데이터가 덤으로 생김
- 수요 변수는 행정안전부 주민등록 인구통계(행정동×연령별)로 서브카테고리별 매칭:

| 서브카테고리 | 수요 변수 |
|---|---|
| 입시·보습 (초/중/고) | 해당 연령대 학령인구 (행정동별) |
| 예체능 | 초등 인구 + 배후 주거 규모 |
| 외국어·직업 (성인) | 직장인구·대학 인접성 |

**분석 규칙:**
- 경쟁밀도·성장률·폐업률은 **서브카테고리 단위로 산출** (전체 학원 수는 참고치로만)
- ERD: `학원` 테이블 + `교습과정` 테이블(1:N) — §13 노드-엣지 규칙대로 연결, 각각 11-File Set
- 구현: 서브카테고리별 수요변수 매핑은 `if 계열` 분기가 아니라 설정(VO) + Strategy로 (§5)
- 어린이집도 동일 프레임 적용 가능 (보육 정원·연령별 영유아 인구 — 어린이집정보공개포털 데이터)

**외국인 인구 변수 — 모델링 규칙:**

외국인 밀집 지역(대림동, 안산 원곡동 등)은 상권의 수요 구성이 근본적으로 바뀐 사례다.
단, 이 변수는 **"상권 악화 지표"가 아니라 "수요 구성 변화 지표"로 모델링한다.**

- **실제 효과는 양방향**: 기존 내국인 타겟 업종(입시학원 등)의 수요는 줄지만, 동일 지역에서
  외국인 수요 업종(음식점·송금·통신 등)과 에스닉 상권은 성장한다. 대림동·원곡동은 "죽은 상권"이
  아니라 "고객이 교체된 상권"이며, 총 점포 수·매출로 보면 붕괴가 아닌 재편에 가깝다.
- **분석 방식**: 창업 희망 업종의 타겟 고객(연령·언어·소비 패턴)과 해당 상권의 인구 구성
  (내국인 연령대 + 등록외국인 수·국적·증감률)의 **정합성**을 점수화한다.
  예: *"이 지역은 초등 학령 내국인 인구가 5년간 30% 감소, 등록외국인 20% 증가 →
  입시학원 타겟 수요 축소, 외국인 대상 한국어·직업교육 수요는 증가"*
- **금지 규칙**: 에이전트가 "외국인 비율 높음 = 나쁜 상권" 류의 출력을 생성하지 않도록
  응답 규칙에 명시한다. 차별적 출력은 서비스 신뢰와 법적 리스크(차별 조장) 문제이며,
  분석적으로도 틀렸다(위 양방향 효과). 외국인 변수는 항상 "업종 타겟과의 정합성" 문맥으로만 제시한다.
- **데이터**: 행정안전부 「지방자치단체 외국인주민 현황」(시군구·읍면동, 국적별, 연간),
  서울 열린데이터광장 등록외국인 행정동별 통계 → 학령인구와 동일하게 §5.1 배후인구 축의 세부 구성으로 편입

| 변수 | 감지 소스 |
|---|---|
| 지하철 신설역·GTX 개통 | 국토부 계획 고시 + 뉴스 |
| 재개발·재건축·대규모 입주 | 정비사업 공시, 입주 물량 |
| 대형 시설 개폐점 (백화점·마트·대학 이전) | **뉴스가 사실상 유일한 소스** |
| 젠트리피케이션 (임대료 급등) | 부동산원 임대료 지수 + 뉴스 |
| 대형 오피스 입주·공실 | 뉴스 + 부동산원 공실률 |

### 5.3 뉴스 데이터 — 특이변수 감지기

정형 데이터에 안 잡히는 충격(③·④ 계층)은 뉴스가 센서 역할을 한다. **뉴스는 "특이변수 발생 감지 + RAG 근거 문서" 두 용도.**

| 수집 소스 | 성격 | 용도 |
|---|---|---|
| **빅카인즈 (BIG KINDS)** | 한국언론진흥재단 뉴스 빅데이터 — 공공 성격, 분석 API 제공 | 1순위. 키워드 언급량 시계열, 기간·언론사별 검색 |
| 네이버 뉴스 검색 API | 개발자 API (무료 쿼터) | 실시간 보조, 상권명 검색 |

**활용 3가지:**
1. **지역 이벤트 감지**: "{상권명/역명} + 개통·폐점·재개발·입주" 키워드 매칭 → ④계층 변수 자동 생성
2. **트렌드 감지**: 업종 키워드 언급량 시계열 (예: "무인카페" 급증) → ③계층 변수의 프록시
3. **RAG 근거**: 에이전트 응답에 "이 상권은 2027년 GTX-X 개통 예정 [기사 링크]" 형태로 인용

**경계:**
- 뉴스 **전문 저장은 저작권 문제** → 메타데이터(제목·일자·언론사·URL)와 분석 지표만 저장, 본문은 링크로
- 뉴스 기반 신호는 정형 데이터와 등급을 구분: 정형 지표는 "확인된 사실", 뉴스 신호는 "참고 신호"로 표기 (신뢰도 혼동 방지)
- MVP 범위: 빅카인즈 키워드 언급량 + ④계층 감지까지. 감성분석 등 NLP 고도화는 post-MVP

**설계 원칙**: 전통 변수와 특이변수를 분리된 축으로 모델링한다.
"이 상권의 기초 체력(전통 변수)"과 "외부 충격에 대한 취약도(특이변수)"를 따로 보여줘야
창업자가 "지금 폐업이 많은 이유가 상권이 나빠서인지, 일시적 충격 때문인지"를 구분할 수 있다.
이것이 본 에이전트의 핵심 차별점이다.

### 5.4 코로나 특이변수 분석 프레임 (①계층 충격의 표준 분석 예시)

1. **충격 구간 정의**: 거리두기 단계 시계열 → 업종별 영업제한 강도 매핑
2. **회복 판정**: 상권×업종별 점포 수·매출이 2019년 수준으로 회복했는지 (V자 / L자 / 소멸)
3. **취약도 점수화**: 충격 대비 폐업률 증가폭 → 상권별 회복탄력성 지표
4. RAG 응답 예: *"이 상권의 노래방은 2021년 40% 폐업 후 60%만 회복 — 일시 충격이 아닌 구조적 수요 감소로 판단됨"*

## 7. 브이월드(VWorld) 기반 지도 시각화

**결론: 가능하다.** 단, 역할 분담을 정확히 해야 한다 —
**브이월드는 "지도·공간 레이어"를 제공할 뿐, 성장률·폐업률 지표는 우리가 LOCALDATA로 직접 산출**해서 얹는 구조다.

### 7.1 브이월드가 제공하는 것

| 기능 | API | 용도 |
|---|---|---|
| 배경지도 (2D/3D) | WMTS/XYZ 타일 | 지도 베이스 (OpenLayers/Leaflet 연동) |
| 행정구역 경계 | WFS (시군구·읍면동 폴리곤) | 상권 단위 경계 표시, 단계구분도(Choropleth) 영역 |
| 지오코딩 | Geocoder API | LOCALDATA 업소 주소 → 좌표 변환 |
| 검색 | Search API | 주소·지명 검색 진입점 |
| 연속지적도·건물 | WMS/WFS | (후순위) 필지·건물 단위 상세 뷰 |

- 발급: vworld.go.kr에서 API 키 발급, **서비스 도메인 등록 필요** (데모 사이트 도메인 등록)
- 무료 quota 존재 → §4.3 체크리스트에 호출 제한 확인 추가

### 7.2 시각화 아키텍처

```
[LOCALDATA 개폐업] ─┐
[상가정보]          ├→ 백엔드: 행정동×업종별 지표 산출 ─→ GeoJSON API
[서울 상권분석]     ─┘   (성장률·폐업률·생존율·점포수)        │
                                                            ▼
[브이월드 WMTS 배경지도 + WFS 행정동 경계] ──→ 프론트: 지도 위 오버레이
```

**화면 구성 (MVP):**
1. **단계구분도**: 행정동별 폐업률/성장률을 색상 농도로 표시 (업종 토글: 카페/노래방/부동산)
2. **점포 마커**: 클러스터링된 업소 위치 (지오코딩 결과), 클릭 시 개업일·영업상태
3. **상권 카드**: 행정동 클릭 → 3업종 지표 요약 + 에이전트 분석(RAG) 호출 버튼
4. **시계열 슬라이더**: 2019 → 현재 연도별 변화 (코로나 충격·회복 시각화 — §5.3과 직결)

**지표 정의 (백엔드 산출):**
- 성장률 = (당해 순증 점포 수) / (전년 점포 수) — 개업·폐업 모두 반영한 순증 기준
- 폐업률 = 당해 폐업 수 / 기초 점포 수
- 데이터 흐름상 이 지표 테이블 자체가 ERD의 집계 테이블 1개 = Fractal 11-File Set 1개가 된다

**대안 검토**: 행정동 경계는 통계청 SGIS API로도 제공됨. 브이월드 WFS 응답이 무겁거나 quota가 부족하면 경계 폴리곤만 SGIS로 대체 가능 (배경지도는 브이월드 유지).

## 8. 금융 연계 브레인스토밍

상권 분석이 "여기 들어가도 되나?"에 답한다면, 금융 연계는 **"들어간다면 돈은 어떻게 마련하나?"**까지
이어주는 것이다. 분석 → 자금 조달이 한 흐름이 되면 에이전트의 실질 가치가 완성된다.

### 8.1 연계 시나리오 (단계별)

**① 정책자금 공고 요약 + 원문 링크 (MVP 권장 — 공공데이터만으로 가능)**
- 소상공인시장진흥공단 정책자금(창업자금 대출), 지역신용보증재단 보증, 서울시 자영업지원 등 **공고 문서를 RAG 코퍼스로 수집** → 대상·한도·금리·기한을 표준 카드로 요약하고 **반드시 원문 링크 첨부** → 사용자의 "공고 찾아 헤매는 공수"를 없애는 것이 목표
- 우리는 요약·연계까지만 하고 신청·중개는 하지 않음 (§8.2 규제 경계와 일치)
- 팀명 "정책 공시 RAG 파이프라인"과 정확히 정합 — 이미 만들 파이프라인의 확장이지 새 시스템이 아님
- 예: *"이 상권 카페 폐업률이 평균 이상 → 초기 고정비를 낮추는 게 안전. 소진공 신규창업자금(최대 7천만원, 연 X%)과 서울신보 특례보증 대상입니다 [공고 링크]"*

**공고 수집 소스 목록 (2026-08-24 API 제공 여부 검증 완료):**

| 소스 | 운영 | 수집 방법 (검증됨) | 커버리지 |
|---|---|---|---|
| 기업마당 (bizinfo.go.kr) | 중소벤처기업부 | ✅ **자체 Open API** (지원사업정보, JSON/XML) | **중앙부처+지자체+유관기관 공고 통합 (~1,500건 상시)** — 단일 API로 최대 커버, 1순위 |
| K-Startup (k-startup.go.kr) | 창업진흥원 | ✅ **공공데이터포털 API** (사업공고 조회서비스) + 자체 API | 창업지원사업 — 예비창업패키지 등 패키지형 |
| 중소벤처24 (smes.go.kr) | 중소벤처기업부 | ✅ **공공데이터포털 API** (공고정보 — 중기부 산하기관 통합) | 소상공인 정책자금 융자 공고 포함 |
| 보조금24 | 행정안전부 | ✅ **공공데이터포털 API** (대한민국 공공서비스(혜택) 정보, 7,500여 서비스) | 개인·사업자 보조금 |
| 온통청년 (youthcenter.go.kr) | 한국고용정보원 | ✅ **자체 Open API** (청년정책, 인증키 발급) + 공공데이터포털 API | 청년창업 자금 (타겟 세그먼트) |
| 소진공 정책자금 (semas.or.kr) | 소상공인시장진흥공단 | ⚠️ 공고 API 미확인 → 스크래핑 후보 (상권정보 API와 별개) | 직접대출·희망리턴패키지 |
| 서울신용보증재단 / 지역신보 | 각 재단 | ⚠️ API 없음 → 스크래핑 | 보증 상품 — 지역 밀착 |
| 서울시 자영업지원센터 / SBA | 서울시 | ⚠️ 스크래핑 | 서울 한정 지원사업 (MVP 지역과 일치) |

- **핵심 발견**: 기업마당 API 하나가 중앙부처+지자체+유관기관 공고를 이미 통합 제공 → **MVP는 기업마당+중소벤처24+K-Startup 3개 API로 시작**하고, 스크래핑 소스는 커버리지 공백 확인 후 추가
- **중복 제거 필수**: 동일 공고가 기업마당·중소벤처24·K-Startup에 동시 게시됨 → 공고명+기관+기간 기준 dedup 로직 필요
- 참고 구현: [sole-search](https://github.com/djfksjd/sole-search) — 소상공인24·기업마당 크롤링 + 프로필 기반 자격 판정 에이전트 스킬 (동일 문제를 푼 오픈소스, 자격 판정 5단계 설계 참고 가치)
- **원칙: API 우선, 스크래핑은 API 없는 소스만.** 공공 공고는 대부분 공공누리 라이선스라 수집·재가공 가능하나, robots.txt 준수 + 출처·원문 링크 표기 필수
- **업종 매칭 방법**: 공고문의 지원 대상은 자유 텍스트가 많음 → 수집 시 LLM으로 {대상 업종, 지역, 대상 단계(예비/기창업), 한도, 금리, 마감일}을 **구조화 추출**하여 메타데이터화 → 1차 필터(업종·지역·마감일)는 정형 쿼리, 2차 상세 매칭은 RAG. 이 구조화 추출이 곧 프로젝트명의 "공공 데이터 Chunking"에 해당
- 마감일 지난 공고 자동 만료 처리 (배치 갱신 주기: 일 1회)

**② 창업 비용 시뮬레이션**
- 실거래가·임대동향 데이터로 해당 상권 임대료 추정 + 업종별 표준 창업비용(소진공 실태조사) → **필요 자금 규모 산출** → 자기자본 입력받아 부족분에 대한 정책자금 조합 제안
- 상권 리스크 등급이 높으면 "권장 자기자본 비율"을 높게 제시하는 식으로 분석과 금융을 결합

**③ 월세 vs 매입 대출 계산기 ("건물주 시나리오")**
- 시나리오: *"지금 월세 300을 내는데, 이 상권 상가를 매입하면 얼마이고, 내 신용 기준 대출 이자가 월세보다 싸다면 건물주가 되는 게 낫지 않나?"* — 이 비교를 **예상 계산까지만** 제공
- 입력: 현재 월세, 자기자본, 신용등급(사용자 자가 입력), 대출 기간
- 산출 파이프라인:
  1. **매입가 추정**: 국토부 상업용 실거래가 → 해당 상권 유사 면적 상가 매매 시세
  2. **금리 추정**: 은행연합회 소비자포털 공시 금리를 **1군(시중은행) / 2군(지방·인터넷·저축은행) 평균율**로 집계 → 사용자 자가 입력 신용등급 구간 × 은행군 조합의 평균 금리만 예상치로 적용 (특정 은행 상품은 절대 표시하지 않음 — §8.2 경계 준수 장치이기도 함) + 한국은행 기준금리·COFIX로 보정
  3. **대출 가능액**: 상업용 담보 LTV 통상 60~70% 가정 (가정임을 명시)
  4. **월 부담 비교**: 원리금균등/이자만 납입 시나리오별 월 상환액 vs 현재 월세
  5. **부대비용 포함**: 취득세(상가 4.6%)·중개보수·보유세까지 넣은 총비용 비교 + 손익분기 연차
- 출력 예: *"매입가 추정 4.2억, 자기자본 1.5억 + 대출 2.7억(공시 평균 연 5.2%) → 월 이자 약 117만원. 현재 월세 300만원 대비 월 183만원 절감, 취득 부대비용 회수까지 약 1.1년"*
- **핵심 경계 (규제·정직성)**:
  - 신용도는 **사용자 자가 입력**만 받는다 — 실제 신용정보 조회는 신용정보법·마이데이터 사업자 라이선스 영역이므로 MVP 절대 불가
  - 금리는 은행연합회 **공시 데이터 인용**으로만 표시, "예상치이며 실제 심사 결과와 다를 수 있음" 고지 필수
  - 특정 은행 상품 추천·비교로 가면 대출성 상품 중개에 근접 → **계산기(시뮬레이션)까지만**
- 이 계산기는 상권 분석과 결합될 때 차별화됨: 폐업률 높은 상권이면 *"매입 시 공실 리스크"*를, 성장 상권이면 *"시세 상승 여력"*을 근거 데이터와 함께 병기

**④ 금융기관 제휴 (post-MVP, B2B)**
- 상권×업종 리스크 스코어를 은행·핀테크(개인사업자 대출)의 **여신 심사 참고 데이터로 제공**
- 소상공인 대출은 담보·신용 위주 심사라 "입지 리스크" 데이터가 공백 → 우리 지표가 차별점
- 역방향도 가능: 폐업 위험 상권 기존 사업자에게 희망리턴패키지(폐업·재기 지원) 안내

**⑤ 공제·보험 연계 (post-MVP)**
- 노란우산공제(폐업 대비 공제) 가입 안내를 리스크 등급과 함께 제시

### 8.2 규제 주의사항 (중요)

- **대출 "중개·모집"은 금융소비자보호법상 등록 대상** — MVP는 절대 중개까지 가지 않는다.
- MVP 범위는 **"공공 공고 기반 정보 제공 + 원문 링크"까지**로 한정하면 규제 리스크 없음.
- 금리·한도 등 수치는 반드시 공고 원문 인용(RAG 근거 제시)으로만 표시 — 자체 산출·확약 금지.
- 은행 제휴(③)는 제휴 계약과 법률 검토가 전제이므로 명시적으로 MVP 제외.

### 8.3 MVP 반영 제안

| 항목 | MVP 포함 | 근거 |
|---|---|---|
| 브이월드 지도 + 지표 시각화 | ✅ 포함 | 공공 API만으로 구현 가능, 데모 임팩트 큼 |
| 정책자금 공고 요약+링크 (①) | ✅ 포함 | 기존 RAG 파이프라인의 코퍼스 확장 |
| 창업 비용 시뮬레이션 (②) | ⚠️ 간이 버전만 | 임대료 추정까지만, 자금 조합은 후순위 |
| 월세 vs 매입 계산기 (③) | ✅ 포함 (계산까지만) | 실거래가+공시금리 등 전부 공공데이터, 순수 계산 로직 |
| 금융기관 제휴 (④), 공제 (⑤) | ❌ 제외 | 계약·규제 검토 필요 |

**계산기(③) 추가 데이터 소스**: 은행연합회 소비자포털 공시 금리, 한국은행 ECOS(기준금리·COFIX),
국토교통부 상업용 실거래가 — §4 목록에 은행연합회 공시만 추가하면 됨.
