## 1. 관리자 페이지 4종 (관제실 `/admin`)

eungsang.com의 관제실 구성을 참고했다. 허브(`/admin`)에서 네 방으로 들어간다. 문마다 **상태 배지**가 붙어 지금 들어가 봐야 하는지 보여 준다.

### 1-1. 보안 감사팀 `/admin/security` (15초 갱신)
- **요약**: 최근 24시간 로그인 실패·차단 요청·스캐너 탐색·5xx 등 6개 수치.
- **알림**: 규칙별 경보. 브루트포스 로그인(15분 5회 높음·10회 심각), 스캐너 경로(1시간 3회), 5xx 폭주(15분 5회), 차단 IP 재시도(1시간 5회). 관리자는 알림에서 바로 "24시간 차단"을 누를 수 있다.
- **이벤트**: 종류·IP·기간(24시간·7일·30일) 검색, IP를 누르면 그 IP만 본다, "더 보기"로 이어 붙인다. 디바이스 열(브라우저·OS 요약과 ID)을 보여 준다.
- **감사 로그**: 누가 언제 무엇을 했는지(IP 차단·해제, 프로브, 수집기 실행, 계정 정지, 목록 추가·삭제, 자동 방어 설정 등). 행위 필터가 있다.
- **자동 방어** (켜기/끄기):
  - 로그인 실패: 같은 IP가 15분 안에 10회 실패하면 1시간 차단하고, 풀린 뒤 다시 걸리면 24시간 차단한다.
  - 취약점 스캐너 경로 탐색: 1시간 안에 5회면 24시간 차단하고, 다시 걸리면 7일 차단한다.
  - 꺼도 이미 걸린 차단과 로그인 제한(10분 10회)은 유지된다.
- **블랙리스트**: IP(기간 1시간·24시간·7일·무기한)와 디바이스를 차단하고 해제한다. 지금 쓰는 내 IP·디바이스는 막을 수 없다.
- **화이트리스트**: IP·대역(CIDR)·디바이스를 등록한다. 등록된 대상은 자동 차단과 로그인 횟수 제한에서 빠진다. 관리자가 직접 건 차단은 화이트리스트여도 그대로 막는다. "내 디바이스 넣기" 버튼이 있다.
- 디바이스 식별은 관리자 경로에서 발급하는 쿠키(`metabole_device`, 22자)다. 인증 수단이 아니라 목록에 올릴 대상을 가리키는 표식이다.

### 1-2. 헬스케어실 `/admin/healthcare` (30초 갱신)
- **개요**: LLM 체인(1차 Gemini, 폴백 Ollama)의 가용성, 필수 로컬 모델 설치·적재 상태.
- **사용량**: 24시간·7일 분석 건수·토큰·모델별 집계, 호출 결과(성공·폴백·오류) 추이, 폴백률·오류율(5% 주의·20% 위험), 한국 시각 시간대별 분석 건수.
- **RAG**: 출처별 청크 수와 임베딩 모델.
- **프로브**(관리자 전용): RAG 검색 상위 5건, LLM 한 턴 호출을 직접 실행해 본다.

### 1-3. 설비실 `/admin/facility` (10초 갱신)
- **대시보드**: CPU·메모리·스왑·디스크 게이지(80% 주의·90% 위험), GPU VRAM, 서비스 상태(Postgres·Ollama).
- **추세**: 1시간·6시간·24시간·7일 CPU·메모리·디스크·부하·GPU 사용률·VRAM·온도. 매분 쌓는 표본(`host-metrics-sampler`, 8일 보관)을 쓴다.
- **수집기**: 수집기별 신선도(주기 × 1.5 이내면 정상, 넘으면 지연, 기록이 없으면 누락). 관리자는 가려진 로그 끝 N줄 보기와 "지금 실행"을 쓸 수 있다.
- **데이터베이스**: 연결 수, 버전, 마이그레이션 리비전, pgvector, 큰 테이블.

### 1-4. 인사팀 `/admin/users` (30초 갱신)
- **요약**: 조회된 회원 수, 전체 계정, 접속 정지 수, 활성 관리자 수, 활성 세션 수.
- **목록**: 아이디·이메일 검색, 등급·상태 필터, 가입 방식(비밀번호·구글) 열.
- **관리자가 남의 계정에 할 수 있는 일**: 접속 정지·재개와 세션 종료만 된다. 남의 등급·비밀번호 변경과 계정 추가는 화면과 API에서 없앴다(v0.50). 등급 지정과 테스트 계정 생성은 CLI(`set_admin_role`, `create_admin_user`)로만 한다.
- **본인 패널**: 내 계정명 변경, 내 비밀번호 변경(구글 전용 계정은 비밀번호 처음 설정), 다른 세션 모두 끊기.
- 마지막 활성 관리자는 정지할 수 없다.

### 1-5. 공통
- 관리자 페이지 좌측 상단 로고는 서비스 첫 화면(`/`)으로 간다.
- 세션은 httpOnly 쿠키(`metabole_admin`, 12시간)이고, DB에는 토큰의 sha256만 둔다.
- 보존 정리 CLI(`admin_housekeeping`, 매일 03:30)가 접근 이벤트 90일, 감사 로그 365일, 만료 세션·만료 차단을 지운다.

## 2. 공개 회원 계정 (로그인·회원가입)

- `/login`: 아이디 또는 이메일로 로그인한다. 구글 로그인 버튼은 구글 키가 설정됐을 때만 보인다.
- `/signup`: 아이디·이메일·비밀번호(12자 이상)·비밀번호 확인을 받는다. 가입하면 바로 일반 등급이 된다. 같은 IP의 가입은 1시간에 5회로 제한한다. 오늘 제목 아래 안내 문구("가입하면 일반 등급으로 바로 이용할 수 있습니다.")를 뺐다(FE v0.50.1).
- **구글 로그인**: 인가 코드 + state + PKCE 방식이다. 처음 들어온 구글 계정은 이메일 앞부분으로 아이디를 만들어 일반 등급으로 가입시킨다. 기존 비밀번호 계정과 이메일이 겹치면 자동으로 잇지 않는다.
- **등급**: 일반(관리자 페이지 읽기)·관리자(쓰기). 상단바와 랜딩 헤더에 계정 메뉴(로그인·회원가입 / 아이디·등급·관리자 페이지·로그아웃)를 붙였다.
- **더미 계정**: 아이디 `001`(일반 등급)을 개발 DB에 만들었다. 비밀번호는 문서에 적지 않는다.

## 3. 유사 사례 (리포트 섹션)

"비슷한 일이 예전에 있었을 때 업종마다 무슨 일이 있었고, 그래서 앞으로 무엇이 예상되는가"를 보여 준다. 리포트 섹션 순서는 판정 → 판정 이유 → **유사 사례** → 조건 → 대안 → 지원사업이다.

### 3-1. 어떤 사례와 비교하나
- **이벤트 유형 4가지**:

  | 유형 | 예 | 비교 기간 |
  |---|---|---|
  | 감염병·방역 | 메르스, 코로나19 | 이벤트 뒤 3년(12분기) |
  | 최저임금 | 해마다 인상 | 그 해 4분기 |
  | 근로시간 | 주 52시간제 | 이벤트 뒤 3년(12분기) |
  | 지원금·보상 | 재난지원금, 손실보상 | 그 해 4분기 |

- **유형을 고르는 방법**: 질문 속 단어(코로나·바이러스·최저임금·52시간·주4일·지원금 등)와, 운영자가 등록한 진행 중인 이벤트로 고른다. 유형마다 지난 사례를 최근순으로 최대 3건 본다.
- **안내 문구**: 비교하지 않은 유형은 섹션 끝에 "질문에 "코로나", "52시간", "지원금" 같은 단어를 넣으면 함께 비교합니다."로 안내한다.
- **진행 중인 이벤트 등록**: CLI `register_shock_event`로 유형과 함께 등록한다.

### 3-2. 어떻게 계산하나
- **분기별 비교 기준**: 이벤트 달부터 3개월씩 끊어 분기를 만든다. 분기마다 **이벤트 직전 1년의 같은 분기**와 견준 점포수 증감 차이(%p)를 "평소 대비" 값으로 쓴다.
- **강세·약세 판정**: 평소 대비 ±0.3%p를 넘으면 강세·약세다. 대상 업종의 추세는 분기 과반으로 판단한다.
- **거듭 강세·약세 업종**: 분기마다 강세 +1, 약세 −1로 순점수를 매긴다. 점포 100곳 미만인 업종은 순위에서 뺀다.
- **사례 직전 vs 최근 비교**: 감염병·근로시간처럼 드문 유형은 사례 직전 1년과 최근 1년의 업종 상태(점포 증감, 전 업종 대비, 폐업률)를 견준다. 결과는 "그때보다 약한 상태 / 강한 상태 / 비슷함"이다.
- **지금도 그 상황인가**: 진행 중 이벤트가 없는 유형은 최근 30일 뉴스 제목에서 조치 단어(집합금지·영업제한·거리두기 격상 등)를 센다. 기사가 없으면 창업을 말리지 않고, 조건부 위험으로만 쓴다.
- **범위는 서울 전체**: 내 업종과 비교 업종 모두 서울 전체 인허가 기준이다. 학원·어린이집·편의점·치킨·부동산중개·기타 음식점은 흐름을 비교할 수 없어 뺀다.

### 3-3. 범위를 동·구로 좁히지 않는 이유 (오늘 실측)
자치구 기준 계산을 넣었다가(BE v0.61) 데이터를 확인하고 철회했다(BE v0.63). 확인 방법은 이렇다. 2014~2024년의 매 분기를, 실제로는 아무 일도 없었는데 이벤트가 있었던 것처럼 넣고 계산했다. 이때 강세·약세가 자주 잡히면, 그 범위의 판정은 이벤트가 아니라 원래 있던 흔들림을 잡는 셈이다.

| 범위 | 아무 일 없던 분기가 강세·약세로 잡힌 비율 |
|---|---|
| 서울 전체 한식 / 미용실 | 34% / 40% |
| 점포 1,000곳 넘는 구의 한식 | 58~89% (강남구 4,878곳도 58%) |
| 점포 1,000곳 넘는 구의 카페 | 84~93% |

- 같은 분기에 구와 서울 전체의 판정이 일치한 비율은 한식 기준 22~41%로, 우연 수준(약 33%)이다.
- 비교 업종을 구 안에서 줄 세우면 점포 100~300곳짜리 업종이 1등·꼴찌를 차지하고, 서울 전체와 정반대로 나오기도 했다(예: 관악구에서 감염병 시기 양식이 약세).
- 동 단위는 더 작다(보라매동 한식 124곳, 분기 값이 2~3%p씩 흔들림).
- 그래서 문장에 늘 범위를 적는다. 예: "메르스 유행 이후 12분기 중 **서울 전체 카페**가…", "감염병이 유행했던 시기에 **서울 전체에서** 다른 업종보다 상대적으로 잘 버틴 업종은 양식이었습니다."

### 3-4. 리포트 문장
LLM이 분기 수를 틀리게 조립하거나 유형 문구를 섞어 써서, 핵심 문장은 **코드가 완성 문장으로 만들고** LLM은 그대로 옮기게 했다.
- **사례 요약**: "○○ 이후 12분기 중 서울 전체 카페가 평소보다 약했던 분기는 N분기…"
- **겹친 정책**: 앞 2개 분기까지만 정책 이름을 적고, 나머지는 분기 수로 줄인다. 방향이나 인과("덕분에", "때문에")는 붙이지 않는다.
- **잘 버틴 업종**과 **사례 직전 비교**
- **최근 조치 뉴스**: 건수만 적고, 기사 제목은 인용하지 않는다.
- **대표 사례**: 유형마다 최근 2건에만 문장을 붙이고, 나머지 사례는 LLM에게 넘기지 않는다.
- **근거 표기**: [확인된 사실](사례 근거)과 [참고 신호](뉴스) 표기를 붙이고, 유형마다 사실 → 신호 순서로 쓴다.

### 3-5. 화면
- **유형 칩**: "감염병·방역 · 질문 속 상황", "최저임금 · 진행 중 이벤트"처럼 보여 준다.
- **유형 종합 카드**: 사례 수, 내 업종 추세, 보통 지속 기간, 거듭 강세·약세 업종 칩, 사례 직전 대비 지금 상태, 최근 조치 소식.
- **사례 카드**: 업종 × 분기 **히트맵**. 칸 색이 강세·약세를 나타내고, 내 업종은 굵게 표시한다. 연속 약세 분기 수와 겹친 다른 정책도 적는다.
- **본문 정리**: 근거 표기마다 문단을 나누고 문장마다 줄을 바꾼다. 같은 문장이 되풀이되면 처음 한 번만 보여 준다.
- **덤으로 고친 문제**: 물결표 범위(50~299인)가 취소선으로 보이던 문제를 고쳤다.

- **창업 지원·대출 정보 보기 →** → `/support`
- **← 다른 창업 알아보기** → `/map` (지도에서 동네나 업종을 바꿔 다시 비교)

## 5. 서포트 페이지 `/support` (창업 지원·대출 정보)

API `GET /funding/support?region=&industry=`. LLM 없이 규칙으로만 묶는다.
- **대출·보증**:
  - 한국은행 기준금리와 은행 시설자금대출 평균 금리(기준 월 표시)를 보여 준다.
  - 정책자금 융자·보증 공고를 최대 6건 보여 주고, 우리 구 공고를 앞에 둔다.
- **{구} 전용 지원**: 그 구 사업장만 신청할 수 있는 공고를 최대 6건 보여 준다. 구를 모르면 이 묶음을 그리지 않는다.
- **창업·경영 지원**: 업종 관련 공고를 앞에 두고 "업종 관련" 표시를 단다(최대 8건).
- **상담·신청 창구**: 소상공인 정책자금, 서울신용보증재단, 서울시 자영업지원센터, 소상공인24, K-스타트업, 기업마당.
- **이동 링크**: "필요한 자금 계산하기 →"(`/plan`), "← 분석 결과로"(`/analysis`).
- 자격 확정이 아니라는 안내를 상단에 고정한다. 공고를 못 불러와도 상담 창구는 보여 준다.

**다른 구 전용 공고 판정**
- 구청 공고도 소관기관이 "서울특별시"로 오고, 구 이름은 제목·태그에만 있다.
- 그래서 제목(한글 낱말 첫머리에서만)·태그·소관기관에서 구 이름을 찾는다. "집중구역"의 "중구" 같은 오탐은 막는다.
- 다른 구 전용이면 뺀다. 구를 모르면 구 전용 공고를 모두 뺀다.
- 업종 낱말은 업소를 가리키는 말로 좁혔다. 실측에서 "미용기기"·"헬스케어"가 미용실·헬스장으로 잡혔기 때문이다.

**리포트 지원사업 섹션에도 같은 규칙 적용 (BE v0.62)**
- 관악구 리포트에 은평구 청년식당 공고가 나오던 문제를 고쳤다.
- `GET /funding/candidates`에 `region`을 받는다. 리포트 수집기와 자금 계획 화면이 모두 동 코드를 넘긴다.

## 6. 예상 필요 금액 알아보기 (자금 계획 `/plan` 연결)

- **진입**: 지원 화면의 "필요한 자금 계산하기 →"가 동·업종·예산을 들고 자금 계획으로 간다.
- **지원사업 후보**: 자금 계획의 조달·상담 준비 단계에 나오는 후보 공고도 동을 넘겨, 다른 구 전용 공고를 뺀다(FE v0.49).
- **재진입 초기화 (FE v0.51)**:
  - 문제: 계산 결과를 탭 세션 저장소에 저장했다가 다시 들어올 때마다 복원했다. 입력칸은 기본값인데 결과 카드만 지난 값이라 둘이 맞지 않았다.
  - 수정: 계획은 이제 화면에 머무는 동안만 유지하고 저장·복원하지 않는다. 다시 들어오면 빈 계획서로 시작한다.
  - 제약: 새로고침하거나 다른 화면에 다녀와도 결과가 비워진다.

## 7. 검증

- 백엔드 테스트 1,072개, 프론트엔드 테스트 657개가 모두 통과한다. 프론트엔드 타입 검사도 통과한다(마지막 실행 기준).
- **실데이터 확인**:
  - 유사 사례 API: 범위가 서울 전체이고, 새 주의사항 문구가 나온다.
  - 지원사업 후보 (한식 기준):
    - 관악구 동: 은평구 공고 2건이 빠지고 관악구 공고는 남는다.
    - 강남구 동: 세 공고 모두 빠진다.
  - `/plan` 재진입: 빈 계획서로 시작한다.

## 8. 배포·운영 메모

- **클라이언트 IP**: 자동 방어는 IP 기준이다. 배포 때는 Next 앞에 X-Forwarded-For를 **덧붙이는** 리버스 프록시(nginx `proxy_add_x_forwarded_for`, Cloudflare 등)를 둬야 한다. 그렇지 않으면 IP를 위조해 차단을 피하거나 남을 차단시킬 수 있다.
- **쿠키 설정**: HTTPS로 배포하면 `ADMIN_COOKIE_SECURE=true`로 되돌린다.
- **디바이스 쿠키의 한계**: 쿠키를 지우거나 다른 브라우저를 쓰면 새 디바이스가 된다. 디바이스 차단은 가벼운 차단이라, 끈질긴 상대는 IP 차단과 함께 쓴다.
- **유사 사례의 한계**:
  - 10~12월 분기에는 12월 행정 정리로 몰리는 폐업이 섞인다.
  - 2020~2022년에는 지원금 때문에 폐업이 늦어진 효과가 섞인다.
  - "평소 대비" 값은 이벤트만의 효과가 아니다.
