# 리포트 문장 오독 대응 재평가 (2026-10-06, backend v0.71.0)

risk-band 평가에서 남은 오류 유형을 코드 문장으로 막았다 — 시간대 사람·매출 두 문장 + 배수 낱말, 재난지원 단서를 2020~2022년 수치 옆에만,
생존 절벽·조기 폐업 줄에 지표 뜻, 유사 사례 "평소보다"→"사례 직전 1년 같은 분기보다", 동네 유형 근거 "100곳으로 치면" 표기, 프리필 월매출 이상값 비우기(A).

## 측정 방법
- 평가셋 facts의 고정 문장만 일회성으로 새 형식으로 바꿨다(숫자·판정 그대로): 유사 사례 요약 154개(`summary_sentence` 재계산), 동네 유형 근거 148개(재계산한 `region_profile_quarter`의 같은 동·분기 문장), 프리필 월매출 22건(새 규칙으로 비워지는 조합만). 코드 절(시간대·폐업률·신호 줄)은 실행 시 새 코드가 쓴다.
- 150건 × gemini-2.5-flash·gemma4:12b 1회, 온도 0. 판정은 opus 블라인드 6명, 기준표 v2, 자료 부족 34건 제외 116건. 태그 `wording150`, 비교 기준 `band150`.
- Gemini 첫 실행은 선불 크레딧 소진(402 RESOURCE_EXHAUSTED)으로 전부 실패 — 충전 뒤 Gemini만 다시 돌렸다.
- 유형별 건수는 판정 메모 키워드 집계라 근사다(한 오류가 여러 유형에 걸리기도 한다).

- **Gemini(운영 기본): 겨냥한 유형은 사라졌다(시간대 3→0, 생존·조기 1→0).** 그런데 전체는 14건 그대로 — "2019년 x% → 2026년 y%" 두 점을 "꾸준히 증가/감소"로 옮기는 오류가 1→6건으로 늘었다(e017·e021·e034·e038·e092). 문장 끝 재난지원 단서(중간 연도가 있다는 암시)가 빠지면서 두 점이 추세처럼 읽히는 것으로 보인다.
- **12b: 재난지원 오독은 줄었지만(7→2) 나머지는 그대로이거나 늘었다.** 지표 뜻을 적어도("새로 연 점포의 생존율이 아님") 무시하고 생존율로 옮긴 사례가 여럿(e016·e025·e045·e046). 전체 29.3→33.6%는 구간이 크게 겹친다(1회 실행). 12b는 문장 개선으로 따라오지 않는다 — 폴백 전용 유지.
- 코드 절 검사 150건 문제 0, 해석 p95 Gemini 4.5초·12b 4.5초.
