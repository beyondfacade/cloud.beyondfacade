# 코드 가드 적용 후 리포트 재평가 (2026-10-05, backend v0.67.0)

기준선: `../llm-benchmark-2026-10-05/` (가드 전). 같은 고정 사실 12건, 같은 7개 모델 × 3회, 같은 채점 기준표(`data/eval/report_judge_rubric.md`), 같은 판정 모델(opus)로 판정했다.
수치는 `report.md`(자동 생성)에서 옮겼다. 관문 표는 다시 돌리지 않았다(기준선 캐시 그대로).

## 바뀐 것 (v0.67.0)
1. 판정 절: 등급 이름을 쓰지 말라고 바꾸고, 명시적 등급 단정이 사실과 어긋나면 코드가 판정 절을 사실 문장으로 바꾼다. 판정 절은 끝까지 모았다가 한 번에 내보낸다.
2. 링크·공고 번호: 쓰지 말라고 바꾸고(화면 카드가 원문 링크를 보여 준다), 출력 스트림에서 URL·공고 번호를 지운다.
3. 신뢰 태그: 판정·이유·조건·대안·지원사업 절 본문이 태그 없이 시작하면 `[확인된 사실]`을 붙인다(유사 사례 절 제외).
4. 지원사업 절 끝에 "금리·한도는 예상치…원문 확인" 고지문을 붙인다.

## 읽기
- **가드가 겨냥한 실패는 사라졌다.** 12b의 공고 번호·URL 오기(지어내기 0.39)는 0.00 — 프롬프트에서 링크를 빼자 12b가 링크를 아예 쓰지 않았다(링크 제거 개입 0회). 신뢰 태그는 모든 모델이 섹션 180개 중 174~180개를 빠뜨려 코드가 붙였다 — 프롬프트로는 지켜지지 않는 규칙이었다. Gemini의 판정자 위반은 11 → 4.
- **로컬 모델은 여전히 엄격 게이트를 통과하지 못한다.** 12b·e4b의 남은 탈락 사유는 규칙 위반과 첫 글자 지연이다. 남은 위반은 가드가 다루지 않은 새 유형이다:
  1. **대안 절 등급 바꿔 쓰기** — 대안 동네·업종의 등급(clear 등)을 "판정 없음"·"조건부"로 옮겨 적음. 12b 12건 중 5건(s03·s07·s08·s11·s12), e4b 2건. 판정 절과 같은 종류의 실패이며, 화면의 대안 카드(`alternatives-cards`)가 등급을 이미 보여 준다.
  2. **뉴스 없을 때 [참고 신호] 지어내기** — 사실 묶음에 뉴스가 없는데 프롬프트 예시 문장("대부분 논의·실험 단계라…", `analysis_interactor.py` 유사 사례 절)을 그대로 옮김. 12b 4건, Gemini 2건("기사 없음" 문장).
  3. **꺼진 신호를 켜진 신호로 읽기** — e4b 4건. 모델 능력 문제.
  4. Gemini의 "예상 대출 금리 연 4.05%"가 1건 남았다 — 도구 명세의 예시값(`agent_tools.py` `loan_rate` "예 0.0405")이 원인.
- **참고 순위는 그대로다.** 12b 5.83 vs e4b 5.58, 동률(+0.25 [−0.17, +0.67]) → VRAM 우선으로 e4b. 로컬 1위권과 Gemini의 품질 차이는 기준선과 비슷하다.

## 다음 후보 (같은 방식의 코드 가드)
- 대안 절: LLM에게 등급을 쓰지 말라고 하고(대안 카드가 보여 준다), 판정 절과 같은 등급 단정 검사를 대안 절 항목에 적용.
- 유사 사례 절: 뉴스가 비어 있으면 [참고 신호] 문장을 쓰지 말라고 명시하고, 예시 문장은 뉴스가 있을 때의 형식으로만 남김.
- 도구 명세 `loan_rate` 예시값 제거.
- 첫 글자 지연(12b 9.6s, 게이트 5s): 판정 절 버퍼링 대신, 판정 절을 코드 문장으로만 쓰고 LLM 해석을 이유 절로 옮기는 방안.

# 온도 0·seed 42 적용 (같은 날, 일관성 1단계)

확인된 사실: 운영 리포트는 온도를 지정하지 않았다(Gemini 기본 약 1.0, 로컬 모델 기본값). 벤치는 로컬만 0.3이었고 "운영과 같게"라는 주석은 틀렸다. v0.67.0에서 운영·벤치 모두 `REPORT_TEMPERATURE=0.0`, `REPORT_SEED=42`(`apps/agent/domain/services/report_sampling.py`) 단일 원천으로 바꿨다. 같은 커밋에서 도구 명세의 `loan_rate` 예시값(0.0405)을 지웠다.
재측정은 후보 3개(gemini-2.5-flash, gemma4:12b, gemma4:e4b)만, 고정 사실 12건 × 3회. 원자료: `temp0/`.

## 일관성 (같은 시나리오 3회 반복끼리 비교, 1.00 = 완전히 같음)

| 모델 | 결론 일치 | 숫자 일치(Jaccard) | 문장 유사도 | 대안 등급 일치 |
|---|---|---|---|---|
| gemini-2.5-flash | 0.75 → **1.00** | 0.42 → **0.71** | 0.39 → **0.74** | 0.75 → **0.94** |
| gemma4:12b | 1.00 → 1.00 | 0.62 → **0.84** | 0.58 → **0.86** | 0.44 → **0.78** |
| gemma4:e4b | 0.83 → **1.00** | 0.34 → **0.79** | 0.40 → **0.82** | 0.22 → **0.72** |

화살표 왼쪽은 가드 재평가(기본 온도), 오른쪽은 온도 0. 결론 일치 = 회차 간 (완주, 판정 모순 없음, 지어내기 여부)가 모두 같은 시나리오 비율. 대안 등급 일치는 등급별 항목 수까지 비교(다중집합)하며, 두 회차 모두 대안 등급 줄이 없으면 일치로 센다(값이 조금 부풀 수 있다).

## 자동 지표·품질

| 모델 | 완주 | 판정 모순 없음 | 지어내기 | 첫 글자 p50/p95(ms) |
|---|---|---|---|---|
| gemini-2.5-flash | 0.94 → 1.00 | 1.00 → 1.00 | 0.056 → 0.00 | 1,679/2,114 → 1,664/8,679* |
| gemma4:12b | 1.00 → 1.00 | 1.00 → 1.00 | 0.00 → 0.00 | –/9,606 → –/9,489 |
| gemma4:e4b | 1.00 → 1.00 | 1.00 → 1.00 | 0.056 → 0.00 | –/12,694 → –/7,099 |

\* Gemini p95 상승은 2회차 4건의 API 지연(5.9~9.6초)이다. 중앙값은 같다 — 온도와 무관한 네트워크 변동으로 본다.

품질은 기본 온도 회차와 온도 0 회차를 **한 판정 묶음에 섞어** 블라인드로 판정했다(시나리오당 6개 리포트, 같은 판정 세션 — 판정자 잡음 제거).

| 모델 | 충실도 기본→0 | 차이 [95% 구간] | 자연스러움 기본→0 | 차이 [95% 구간] |
|---|---|---|---|---|
| gemini-2.5-flash | 3.50 → 3.25 | −0.25 [−0.83, +0.42] | 3.17 → 3.17 | +0.00 [−0.42, +0.42] |
| gemma4:12b | 2.25 → 2.33 | +0.08 [−0.33, +0.50] | 3.42 → 3.50 | +0.08 [−0.25, +0.42] |
| gemma4:e4b | 2.00 → 1.75 | −0.25 [−0.58, +0.08] | 2.83 → 2.83 | +0.00 [−0.33, +0.33] |

세 모델 모두 구간이 0을 포함한다 — **온도 0은 품질을 바꾸지 않고 일관성만 크게 올렸다.**

## 남은 것
- 온도 0이어도 완전히 같지는 않다(Ollama·Gemini 모두 결정적이지 않음). 특히 대안 등급이 회차마다 다르게 적히는 경우가 12b 22%, e4b 28% 남았다 — 대안 목록을 코드가 쓰는 구조 변경으로 막아야 한다.
- 같은 질문에 글자까지 같은 답은 캐시(의도 관문 칸 + 사실 기준월 키)로만 보장된다.
